This migration is regenerated fresh from schema.prisma on every open-core
sync (Op 9 in open-core-strip.sh) via `prisma migrate diff --from-empty`.
It is a baseline resync, not a schema change — it always reflects
schema.prisma's current full state in one migration rather than
accumulating history, so a large diff here between sync runs is expected
and does not by itself indicate a schema change worth reviewing separately.
